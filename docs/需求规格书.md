# 项目看板 VS Code 插件 · 需求规格书

> 版本：v1.0（讨论定稿）· 2026-09-10
> 状态：需求冻结，待用户说"开始"后进入开发
> 本文档是开发与验收的唯一基准。

---

## 1. 背景与目标

用户同时维护多个异构项目（Qt / Web / ROS 等），笔记以 md 文件分散在各项目文件夹中（当前位于 WSL：`/home/pc/Docs/XuFeng/`）。痛点：

1. 没有统一格式概括项目现状，必须逐个点开 md 才能了解情况
2. 缺少项目总览：哪个项目在哪、什么状态、进展到哪，全靠记忆
3. 进入项目环境繁琐：需手动逐个打开软件、终端、文档
4. VS Code 自带 Markdown 预览不支持所见即所得编辑，不如 Typora

目标：一个 VS Code 插件，提供**项目卡片看板 + 文档树 + 文档预览**三栏视图，一键进入项目工作区，数据主权永远属于纯文本 md 文件。

## 2. 笔记目录自动发现机制（类 .gitignore 模式）

插件**不做全局配置**。在笔记根目录放置一个配置文件，VS Code 打开该文件夹时插件自动生效。

### 2.1 配置文件

- 文件名：`.projectboard.json`
- 位置：笔记根目录（如 `/home/pc/Docs/XuFeng/.projectboard.json`）
- 插件激活条件：当前打开的工作区根目录存在该文件；不存在则插件静默不打扰

### 2.2 配置内容

```json
{
  "projectDirs": ["地面站", "数据大屏"],
  "projectsRoot": ".",
  "hubFile": "README.md",
  "staleDays": 30,
  "archiveFolder": "已完成"
}
```

| 字段 | 含义 | 缺省值 |
|---|---|---|
| `projectDirs` | **检测目录白名单**：看板只统计列表中的项目目录；条目可写相对根目录的路径或绝对路径。**缺省或为空数组时不读取任何目录** | `[]` |
| `projectsRoot` | 新建项目的存放位置，同时是 `projectDirs` 相对条目的解析基准 | `.`（根目录本身） |
| `hubFile` | 项目主文件名 | `README.md` |
| `staleDays` | 超过 N 天未编辑标记"疑似搁置" | `30` |
| `archiveFolder` | 归档文件夹名（可选，用于统计时排除） | `已完成` |

### 2.3 项目识别规则

- `projectDirs` 列表中**含有 hubFile 且 frontmatter 合法**的目录 = 一张项目卡片
- 列表为空或缺省 → 看板不显示任何项目（白名单机制，不自动扫描）
- 列表中的目录缺 hubFile 时不出现在看板（可通过"新建项目"初始化并自动登记进白名单）
- 文件变更通过监听自动刷新看板，无需手动刷新

### 2.4 运行环境说明

- 笔记在 WSL：用户通过 VS Code Remote-WSL 打开文件夹时，插件在 WSL 侧运行，原生读写 `/home/pc/...`
- 跨系统启动：WSL 内可直接调用 Windows 程序（`wt.exe`、`explorer.exe`、`powershell.exe` 启动 .lnk），故"启动工作区"功能不受笔记位置影响
- `code:` 字段允许写 Windows 路径（`D:\Dev\...`）或 WSL 路径，插件按当前运行环境自动转换（`wslpath` 互转）

## 3. README.md 模板（数据格式定稿）

每个项目一个 `README.md` 作为主文件，结构如下：

```markdown
---
name: 地面站（QGC二次开发）
type: qt                # qt / web / ros / 其他（自定义任意值）
status: doing           # doing 进行中 / paused 暂停 / blocked 卡住 / done 完结
focus: 电机测试逆映射；UOM上报    # 当前焦点。可空：留空时自动识别项目内最新至多两条未勾选任务；填写则手动优先
code: D:\Dev\Proj\QGC5-XF\qgroundcontrolfork   # 代码目录，可空
repo: https://github.com/XuFeng/qgroundcontrolfork  # 远程仓库，可空
branch: main            # 可选；缺省时自动读取 code 目录 git 当前分支
tags: [qgc, mavlink, 安卓]
---

## 需求
- [x] 已完成任务（保留不删，计入进度分子）
- [ ] 未完成任务
- [-] 搁置任务（不计入进度分母）

## 问题
（已知 bug、待确认事项，自由格式，一行一条）

## 笔记
（参数、路径、踩坑记录，完全自由书写，插件不解析）

## 草稿
（提示词草稿、临时想法，插件不解析、不统计）
```

规则：

- **插件解析卡片只看 frontmatter**；正文仅统计复选框
- 进度 = 全文 `[x]` ÷（`[x]` + `[ ]`），`[-]` 不计入分母
- `focus` 留空时自动识别：按文件修改时间升序扫描，取最新至多两条非空未勾选任务文本（过滤空占位项，清理 Markdown 语法，截断 30 字）；手动填写 `focus` 则覆盖自动值
- 固定区块名四个：`需求`、`问题`、`笔记`、`草稿`；`草稿` 区块永不解析
- 多分支项目：一张卡，正文用下级标题区分分支（如 `### 主分支` / `### TC特供`）
- 完成任务由用户手动归档（剪切到归档文件），插件不自动清理
- 除 frontmatter 与四个区块名外，其余写法零约束；子文档（VibeCoding/ 等）零约束

## 4. 看板 UI 与交互定义

三栏布局（设计稿：`plugin-design-mockup.html` / `vscode-plugin-design.png`）。

### 4.1 Activity Bar

- 看板图标常驻 VS Code 左侧图标列，点击展开看板视图

### 4.2 顶栏

| 元素 | 功能 |
|---|---|
| 搜索框（Ctrl+K） | 模糊匹配项目名、tags、focus |
| 状态筛选 | 全部 / 进行中 / 暂停 / 卡住 / 完结 / 疑似搁置 |
| 类型筛选 | 全部 / qt / web / ros / …（从现有项目自动收集） |
| 刷新 | 手动重扫（平时靠文件监听自动刷新） |
| ＋新建项目 | 弹窗填名称+类型 → 自动建文件夹 + 按模板生成 README.md |

### 4.3 左1 · 项目卡片列表

卡片元素：项目名、**git 分支标签**（`⎇ main`，与类型标签并排）、类型标签（qt 紫 / web 蓝 / ros 绿）、状态点（绿=进行中 / 黄=暂停 / 灰=疑似搁置）、焦点、进度条与百分比、待办数 · 问题数、更新日期、三个操作按钮。

数据来源：

- 分支标签：**缺省自动读取 `code` 目录的 git 当前分支**；`code` 未配置时读 frontmatter `branch:` 字段；两者皆无不显示
- 疑似搁置：超过 `staleDays` 天无任何文件编辑，卡片自动置灰沉底；编辑文件即自动恢复

交互：

- 单击卡片 → 选中，左2 显示文档树，右侧预览 README
- 右键卡片 → 菜单：标记 进行中/暂停/完结（自动改写 frontmatter `status`）
- 排序：最近更新在前，疑似搁置沉底

**三个按钮：**

| 按钮 | 左键 | 右键 | 数据字段 | 未配置时 |
|---|---|---|---|---|
| 📂 代码 | VS Code 新窗口打开 `code` 目录 | 文件管理器中打开 | `code:` | 置灰 |
| 🚀 启动工作区 | 按序执行工作区启动项（见第 5 节） | 编辑工作区配置（跳转 README frontmatter） | `workspace:` | 点击插入配置模板 |
| 🔗 Repo | 默认浏览器打开 `repo:` URL | 复制 URL 到剪贴板 | `repo:` | 置灰 |

### 4.4 左2 · 文档树

- 显示选中项目的整个笔记文件夹，**默认全部展开、全部显示，长文件名换行不省略**
- 单击文件 → 右侧预览；双击 → 在 VS Code 编辑器中打开编辑
- 文件夹可手动折叠，但默认状态为展开

### 4.5 右侧 · 文档预览

- 渲染 Markdown：frontmatter 显示为信息条；复选框带勾选/搁置/删除线样式
- 顶部标签页可切换已打开的文档
- 演进路线见第 6 节（可点击复选框 → WYSIWYG 编辑）

## 5. 工作区启动器（🚀 按钮）

### 5.1 配置格式（写在 README frontmatter）

```yaml
workspace:
  - name: 代码
    type: vscode        # VS Code 打开文件夹
    path: D:\Dev\Proj\QGC5-XF\qgroundcontrolfork
  - name: AI终端
    type: app           # 任意程序 + 参数
    run: wt.exe
    args: wsl -e codex
    delay: 2            # 可选，等上一项 N 秒
  - name: 参考文档
    type: url           # 浏览器打开网页
    url: https://ardupilot.org/...
  - name: 窗口布局
    type: powertoys     # 启动 PowerToys Workspaces 桌面快捷方式
    lnk: C:\Users\PC\Desktop\地面站工作区.lnk
  - name: 素材文件夹
    type: explorer      # 文件管理器打开
    path: D:\Dev\Docs\XuFeng
```

五种类型：`app` / `vscode` / `url` / `explorer` / `powertoys`。

### 5.2 行为

- 按顺序逐项启动，右下角通知显示进度（"正在启动 2/4：AI终端"）
- 单项失败不阻塞后续项，结束时汇总报告成功/失败
- 未配置时点击按钮 → 自动往 frontmatter 插入注释完善的模板，引导填写

### 5.3 PowerToys 集成（已验证）

- PowerToys Workspaces 无官方 API/CLI，但保存工作区时可生成桌面快捷方式（.lnk），该快捷方式可被任何程序启动
- 插件通过 `type: powertoys` 启动 .lnk，窗口位置记忆由 PowerToys 负责，插件零成本获得布局恢复能力
- 用户在 PowerToys 中捕获/编辑布局，在 README 中引用 .lnk 路径，职责分离

## 6. Markdown 编辑体验（v1 直接集成，定稿）

- **v1 即集成 Vditor**（https://github.com/Vanessa219/vditor ，MIT 开源），右侧文档面板使用其 IR（即时渲染）模式，提供 Typora 式所见即所得编辑
- 源文件始终是纯 md，Vditor 只是编辑"皮肤"，不绑架数据格式
- 编辑内容防抖自动回写源文件；复选框在编辑视图内直接点击切换
- 不再设 v1.5 / v2 分期

## 8. 数据安全原则

1. 一切数据存于纯文本文件（md + .projectboard.json），插件只做索引和视图
2. 插件写操作仅限：勾选状态回写、status 字段修改、新建项目模板生成、工作区模板插入——均可被 git 追踪
3. 建议用户对笔记根目录启用 git 版本管理，作为误操作保险
