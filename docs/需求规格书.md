# 项目看板 VS Code 插件 · 需求规格书

> 版本：v1.1（集中项目配置）· 2026-10-22
> 状态：已实现，持续迭代
> 本文档是开发与验收的唯一基准。

---

## 1. 背景与目标

用户同时维护多个异构项目（Qt / Web / ROS 等），笔记以 md 文件分散在各项目文件夹中（当前位于 WSL：`/home/pc/Docs/XuFeng/`）。痛点：

1. 没有统一格式概括项目现状，必须逐个点开 md 才能了解情况
2. 缺少项目总览：哪个项目在哪、什么状态、进展到哪，全靠记忆
3. 进入项目环境繁琐：需手动逐个打开软件、终端、文档
4. VS Code 自带 Markdown 预览不支持所见即所得编辑，不如 Typora

目标：一个 VS Code 插件，提供**项目卡片看板 + 文档树 + 文档预览**三栏视图，一键进入项目工作区，数据主权永远属于纯文本 md 文件。

---

## 2. 笔记目录自动发现机制（类 .gitignore 模式）

插件**不做全局配置**。在笔记根目录放置一个配置文件，VS Code 打开该文件夹时插件自动生效。

### 2.1 配置文件

- 文件名：`.projectboard.json`
- 位置：笔记根目录（如 `/home/pc/Docs/XuFeng/.projectboard.json`）
- 插件激活条件：当前打开的工作区根目录存在该文件；不存在则插件静默不打扰

### 2.2 配置内容

```json
{
  "projectDirs": ["地面站", "数据大屏"],
  "projects": {
    "地面站": {
      "name": "地面站（QGC二次开发）",
      "type": "qt",
      "status": "doing",
      "code": "D:/Dev/Proj/QGC5-XF/qgroundcontrolfork",
      "repo": "https://github.com/XuFeng/qgroundcontrolfork",
      "branch": "main",
      "tags": ["qgc", "mavlink"],
      "workspace": []
    },
    "数据大屏": { "name": "数据大屏", "type": "web", "status": "doing" }
  },
  "projectsRoot": ".",
  "hubFile": "README.md",
  "staleDays": 30,
  "archiveFolder": "已完成"
}
```

| 字段 | 含义 | 缺省值 |
|---|---|---|
| `projectDirs` | **检测目录白名单**：看板只统计列表中的项目目录；条目可写相对根目录的路径或绝对路径。**缺省或为空数组时不读取任何目录** | `[]` |
| `projects` | 项目配置映射，键必须与 `projectDirs` 中的路径完全一致；值包含 name/type/status/code/repo/branch/tags/workspace | `{}` |
| `projectsRoot` | 新建项目时文件夹选择器的默认位置，同时是 `projectDirs` 相对条目的解析基准 | `.`（根目录本身） |
| `hubFile` | 项目主文件名 | `README.md` |
| `staleDays` | 超过 N 天未编辑标记"疑似搁置" | `30` |
| `archiveFolder` | 归档文件夹名（可选，用于统计时排除） | `已完成` |

### 2.3 项目识别规则

- `projectDirs` 列表中**含有 hubFile**的目录 = 一张项目卡片
- 列表为空或缺省 → 看板不显示任何项目（白名单机制，不自动扫描）
- 列表中的目录缺 hubFile 时不出现在看板（可通过"新建项目"初始化并自动登记进白名单）
- 文件变更通过监听自动刷新看板，无需手动刷新

### 2.4 运行环境说明

- 笔记在 WSL：用户通过 VS Code Remote-WSL 打开文件夹时，插件在 WSL 侧运行，原生读写 `/home/pc/...`
- 跨系统启动：WSL 内可直接调用 Windows 程序（`wt.exe`、`explorer.exe`、`powershell.exe` 启动 .lnk），故"启动工作区"功能不受笔记位置影响
- `code:` 字段允许写 Windows 路径（`D:\Dev\...`）或 WSL 路径，插件按当前运行环境自动转换（`wslpath` 互转）

## 3. 集中项目配置与 Markdown 正文

每个项目的配置均放在根目录 `.projectboard.json` 的 `projects` 对象中，按 `projectDirs` 中的目录路径索引；相对路径以 `projectsRoot` 为基准，绝对路径保持不变。

项目字段：`name / type / status / code / repo / branch / tags / workspace`。名称缺省为目录名，类型缺省为 `other`，状态缺省为 `doing`，其余字段可省略。自定义类型按原始字符串保存。`focus` 字段已废弃，不再存储。

每个项目一个 `README.md` 作为主文件，只写正文，新建项目模板如下：

```markdown
## 需求
- [x] 已完成任务（保留不删，计入进度分子）
- [ ] 未完成任务
- [-] 搁置任务（不计入进度分母）

## 草稿
（提示词草稿、临时想法，插件不解析、不统计）

## 问题
（已知 bug、待确认事项，自由格式，一行一条）

## 笔记
（参数、路径、踩坑记录，完全自由书写，插件不解析）
```

- 进度 = 项目全部 Markdown 中 `[x]` ÷（`[x]` + `[ ]`），排除归档目录与草稿区块，`[-]` 不计入分母。
- 新建模板区块顺序：`需求`、`草稿`、`问题`、`笔记`；其他写法不约束。子文档无需元信息。
- 首次加载旧项目时，自动把 frontmatter 中的插件字段迁移到根配置；已有根配置时以根配置为准。
- 迁移前备份根配置为 `.projectboard.json.projectboard.bak`、项目主文件为 `.README.md.projectboard.bak`（hubFile 自定义时使用对应文件名），不覆盖已有备份；内容不同时另存带时间戳的备份版本。
- 根配置成功保存后，才移除 Markdown 中的插件字段（包括废弃的 `focus`）；非插件 frontmatter 字段和正文保留，维持原文件修改时间。
- 无法解析配置或旧 frontmatter、无法备份时，停止迁移并提示错误；不得用默认值覆盖原配置。重复加载不会重复迁移。
- 右键修改状态、工作区模板插入、新建项目均写入根配置，编辑 Markdown 不再修改项目元信息。

## 4. 看板 UI 与交互定义

三栏布局（设计稿：`plugin-design-mockup.html` / `vscode-plugin-design.png`）。

### 4.1 Activity Bar

- 看板图标常驻 VS Code 左侧图标列，点击展开看板视图

### 4.2 顶栏

| 元素 | 功能 |
|---|---|
| 搜索框（Ctrl+K） | 模糊匹配项目名、目录名、tags |
| 状态筛选 | 全部 / 进行中 / 暂停 / 卡住 / 完结 / 疑似搁置 |
| 类型筛选 | 全部 / qt / web / ros / …（从现有项目自动收集） |
| 刷新 | 手动重扫（平时靠文件监听自动刷新） |
| ＋新建项目 | 选择存放文件夹（默认 projectsRoot）→ 填名称+类型 → 在所选文件夹下新建同名子文件夹并生成 README.md，自动登记进 projectDirs；同名目录已存在时禁止创建，任一步取消不写入文件 |

项目类型支持选择内置类型和现有项目使用的类型，也可直接输入新类型并回车创建；去除首尾空格，不能为空。新类型保存到根配置后，自动出现在后续新建项目的候选列表与看板类型筛选中。

### 4.3 左1 · 项目卡片列表

卡片元素：项目名、**git 分支标签**（`⎇ main`，与类型标签并排）、类型标签（qt 紫 / web 蓝 / ros 绿）、状态点（绿=进行中 / 黄=暂停 / 灰=疑似搁置）、进度条与百分比、待办数 · 问题数、更新日期、三个操作按钮。

数据来源：

- 分支标签：**缺省自动读取 `code` 目录的 git 当前分支**；`code` 未配置时读根配置的 `branch` 字段；两者皆无不显示
- 疑似搁置：超过 `staleDays` 天无任何文件编辑，卡片自动置灰沉底；编辑文件即自动恢复

交互：

- 单击卡片 → 选中，左2 显示文档树，右侧预览 README
- 右键卡片 → 菜单：标记 进行中/暂停/完结（自动改写根配置中的 `status`）
- 排序：最近更新在前，疑似搁置沉底

**三个按钮：**

| 按钮 | 左键 | 右键 | 数据字段 | 未配置时 |
|---|---|---|---|---|
| 📂 代码 | VS Code 新窗口打开 `code` 目录 | 文件管理器中打开 | `code:` | 置灰 |
| 🚀 启动工作区 | 按序执行工作区启动项（见第 5 节） | 编辑工作区配置（打开根目录 .projectboard.json） | `workspace:` | 点击插入配置模板 |
| 🔗 Repo | 默认浏览器打开 `repo:` URL | 复制 URL 到剪贴板 | `repo:` | 置灰 |

### 4.4 左2 · 文档树

- 显示选中项目的整个笔记文件夹，**默认全部展开、全部显示，长文件名换行不省略**
- 单击文件 → 右侧预览；双击 → 在 VS Code 编辑器中打开编辑
- 文件夹可手动折叠，但默认状态为展开

### 4.5 右侧 · 文档预览

- 文档顶栏提供“固定宽度 / 自适应宽度”切换，默认固定内容宽度 800px；自适应模式铺满编辑栏并保留两侧 16px 留白，便于阅读宽表格。选择保存在看板状态中，切换文档和重载窗口后恢复。切换宽度不修改文档内容，不重建编辑器。
- Ctrl+X 剪切应同时复制并移除选中内容，支持撤销、重做和自动保存。任务行首次 Ctrl+V 应直接插入或替换选中文字，复选框保持渲染与勾选状态；行首光标落在复选框前时，粘贴到复选框后的正文开头。保留 Vditor 的 Markdown、富文本与文件粘贴处理。

- 渲染 Markdown 正文；复选框带勾选/搁置/删除线样式
- 顶部标签页可切换已打开的文档
- 演进路线见第 6 节（可点击复选框 → WYSIWYG 编辑）

## 5. 工作区启动器（🚀 按钮）

### 5.1 配置格式（写在根配置的 projects[目录路径].workspace）

```json
"workspace": [
  { "name": "代码", "type": "vscode", "path": "D:/Dev/Proj/QGC5-XF/qgroundcontrolfork" },
  { "name": "AI终端", "type": "app", "run": "wt.exe", "args": "wsl -e codex", "delay": 2 },
  { "name": "参考文档", "type": "url", "url": "https://ardupilot.org/..." },
  { "name": "窗口布局", "type": "powertoys", "lnk": "C:/Users/PC/Desktop/工作区.lnk" },
  { "name": "素材文件夹", "type": "explorer", "path": "D:/Dev/Docs/XuFeng" }
]
```

五种类型：`app` / `vscode` / `url` / `explorer` / `powertoys`。

### 5.2 行为

- 按顺序逐项启动，右下角通知显示进度（"正在启动 2/4：AI终端"）
- 单项失败不阻塞后续项，结束时汇总报告成功/失败
- 未配置时点击按钮 → 自动往根配置对应项目的 workspace 插入模板，并打开根配置引导填写

### 5.3 PowerToys 集成（已验证）

- PowerToys Workspaces 无官方 API/CLI，但保存工作区时可生成桌面快捷方式（.lnk），该快捷方式可被任何程序启动
- 插件通过 `type: powertoys` 启动 .lnk，窗口位置记忆由 PowerToys 负责，插件零成本获得布局恢复能力
- 用户在 PowerToys 中捕获/编辑布局，在根配置中引用 .lnk 路径，职责分离

## 6. Markdown 编辑体验（v1 直接集成，定稿）

- **v1 即集成 Vditor**（https://github.com/Vanessa219/vditor ，MIT 开源），右侧文档面板使用其 IR（即时渲染）模式，提供 Typora 式所见即所得编辑
- 源文件始终是纯 md，Vditor 只是编辑"皮肤"，不绑架数据格式
- 编辑内容防抖自动回写源文件；复选框在编辑视图内直接点击切换
- 不再设 v1.5 / v2 分期

## 8. 数据安全原则

1. 一切数据存于纯文本文件（md + .projectboard.json），插件只做索引和视图
2. 插件写操作仅限：勾选状态回写、status 字段修改、新建项目模板生成、根配置更新与旧版配置迁移（迁移前备份）——均可被 git 追踪
3. 建议用户对笔记根目录启用 git 版本管理，作为误操作保险
